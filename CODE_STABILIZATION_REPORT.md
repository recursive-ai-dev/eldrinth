# Code Stabilization Report

Scope: the whole `src/` tree. That covers the React shell (`App`, every component), the zustand store, the engine (`engine.ts`), the core loop, world state, the save store (`slots.ts`), the region repository and worker, the simulation systems, quests and escalation, and the sprite atlas loader. Baseline before any edit: typecheck clean, 218/218 tests passing.

## Changes Applied
| Priority | Location | Defect | Fix | Regression Test |
|---|---|---|---|---|
| P1 (data loss) | `src/components/GameCanvas.tsx` (init `.catch`) | `game.init()` can succeed and `game.loadWorld(snapshot)` can then throw, for example on a malformed save that passes the shallow checks in `slots.load`. The engine is still `initialized` and not `ended`, so the autosave stayed armed. It wrote the half-restored world over the player's slot on the 10 s interval, when the tab was hidden, and again on unmount. All of that happened while the error screen said the autosave was untouched. Reproduced: 3 overwrites. | Set the existing `fatal` latch in the init-failure path, so `checkpoint()` refuses to write. This is the same guard the fatal-loop path already uses. | `GameCanvas.test.tsx` › "does not autosave a world whose snapshot failed to restore" (fails before the fix, passes after) |
| P2 (race) | `src/game/engine.ts` `saveWorld()` | When the player dies in a reset-on-death fortress and the wayfire is in another region, `discardCurrentRegion` is set and the respawn awaits `regions.acquire()`. If an autosave (interval or tab-hide) lands inside that await, `saveWorld()` → `rememberRegion()` used up the discard flag. The transition then stored the half-cleared fortress, so the reset silently never happened. The window is real whenever the checkpoint region is not cached, for example right after resuming a save made inside a fortress. | While a discard is pending, `saveWorld()` deletes the region's stored state without clearing the flag. The transition still applies and clears it. | `src/game/respawnDiscard.test.ts` uses a gated `RegionSource` to hold the overworld load open across an autosave (fails before, passes after) |
| P2 (input) | `ContentWarning.tsx`, `TitleScreen.tsx`, `IntroSequence.tsx`, `EndScreen.tsx` (window keydown handlers) | The Enter/Space shortcuts ignored `KeyboardEvent.repeat`. One held Enter dismissed the content warning. Each next screen mounted in time to catch the same key's auto-repeat, so the title screen started a run in the first empty slot (or continued slot 1) at a difficulty the player never picked, and the intro then advanced one shot per repeat and skipped itself. Space held from the final fight skipped the ending the same way. | `if (e.repeat) return;` at the top of each of the four handlers. A fresh press behaves exactly as before. | `src/components/keyRepeat.test.tsx`: 4 cases, all fail before and pass after |
| P3 (state desync) | `src/game/engine.ts` `initialize()`, `src/App.tsx` `onReady` | "Reload Region" after an engine crash builds a fresh engine under the same shell. The dialogue, pause and journal state in the store and in `App` still belonged to the dead engine. A stale dialogue box sat over the new world. The new engine had no dialogue, so advancing it did nothing and it stayed until some unrelated dialogue replaced it. A journal left open had the same problem, and keys typed into its note field also moved the player. | The engine now reports `onDialogue(null)` and `onPause(false)` at the end of `initialize()`, next to its existing journal and HUD publication. `App`'s `onReady` closes the journal. For a normal start, where these are already clear, nothing changes. | `src/game/engine.initProjection.test.ts` (fails before, passes after). The `App` journal reset has no automated test (see Deferred Risks). |

One existing test changed. `pauseControl.test.ts` recorded every `onPause` call from boot onward. Boot now announces its initial `false` on purpose, so the test asserts that value and then counts toggles only. The assertion that each toggle produces exactly one call is unchanged.

## Deferred Risks
- **`App.onReady` journal reset has no automated test.** `App` has no test harness, and adding one would mean mocking the save store, engine and every child component. Containment: the change is one state-setter call that only runs when a fresh engine becomes ready, and the engine side of the same desync is covered by `engine.initProjection.test.ts`.
- **A malformed save can still fail to load.** The shallow validation in `slots.load` accepts saves that `WorldState.restore` or `publishJournal` later throw on, for example a non-array `journal` or `quests.facts`. The P1 fix makes this safe, because the slot is no longer overwritten and the error screen is accurate. Deep schema validation would be a behavior change to save compatibility across the v1–v4 migrations, so it was not added blind. Containment: the player keeps the original save and gets a clear error with Retry or Return to Title.
- **A failed cross-region respawn leaves the player in place.** If `changeRegion()` fails during a respawn (the worker errors), the failure is logged and the player stays where they died with full health. The discard is still honoured with the P2 fix. A proper retry or recovery flow would be new behavior. Containment: the next gate or doorway transition works normally, and autosaves stay consistent.
